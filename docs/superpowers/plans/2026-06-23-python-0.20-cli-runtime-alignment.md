# Python SDK 0.13.0 — CLI Runtime + Fallible Stream Alignment (Rust 0.20.0 parity)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the Python SDK (`sdks/python/motosan_ai/`, currently `0.12.1`) to parity with Rust `0.20.0`'s "CLI runtime + fallible stream" feature set, released as Python **0.13.0**. Six features ship in one release, F1 first as the foundation:

- **F1 Fallible stream (FOUNDATION):** every HTTP provider's `stream()` async generator RAISES `motosan_ai.error.StreamError` mid-iteration on a transport/parse fault instead of swallowing it. `collect_stream` already propagates a raise (no change there); the client retry loop must NOT retry a mid-stream raise.
- **F2 cwd setters:** `claude_code` + `gemini_cli` gain a working-directory setter → child runs there via `asyncio.create_subprocess_exec(cwd=...)`. `codex_cli` already has its cwd-equivalent (`cd()` → `--cd` argv flag) — verify, do not re-add.
- **F3 session continuity:** add `session_id` to `StreamEvent` + `ChatResponse`; readback the provider's session id from CLI events; `resume()`. Some CLI session builders already exist — verify/wire, do not re-implement.
- **F4 per-run env injection:** `.env(k,v)` / `.envs(map)` on the 3 CLI providers → child env merged over an `os.environ` copy (parent unmutated); secrets redacted from `repr`.
- **F5 CLI tool-call stream events:** `stream()` surfaces `tool_call_start → tool_call_args → tool_call_end`. Blocking `chat().tool_calls` stays empty for CLI.
- **F6 configurable timeout:** `.timeout(secs)` / `.no_timeout()` on the 3 CLI providers; defaults Claude 300s, Codex 600s, Gemini 600s; a per-read stall deadline RAISES a timeout error.

**Architecture:** Six independent, separately-shippable milestones (one PR each), applied in order. F1 changes shared stream plumbing + all 6 HTTP providers. F2–F6 each thread a provider-config field into the spawn sites (`chat()` blocking + `stream()` generator) of the three CLI providers, mirroring the Rust builder/`SpawnConfig` idiom. Shared-type changes (`StreamEvent.session_id`, `ChatResponse.session_id`) are additive trailing fields with `= None` defaults — every existing constructor is kwargs-only, so they cannot break callers. Python is async-only: builder methods return `self`; callers use `asyncio.run()`.

**Tech Stack:** Python 3.11+, `asyncio`, `asyncio.create_subprocess_exec`, `httpx`, `pytest` + `pytest-asyncio` + `respx`. No new dependencies. Gates: `fmt` (formats Rust+Python+TOML+Nix), `check-python` (`ruff` lint → `ruff format --check` → `pytest`).

**Source basis:** Rust 0.20.0 (`sdks/rust/`); the Rust plan that shipped it: `docs/superpowers/plans/2026-06-09-cli-runtime-provider-changes.md`. Six verified Python port contracts (R1–R6) underlie every task below. Current Python baseline: `0.12.1`.

### Design Decisions (resolved by the lead; "open during plan review — object here to change")

These four resolutions are LOCKED into the tasks below with exact values.

- **Q1 — decode failures:** in EVERY SSE provider, PRE-FILTER empty / whitespace / `[DONE]` data lines BEFORE `json.loads` (add this to `anthropic.py` & `openai.py`, which lack it; `gemini.py` already has it). THEN a non-empty frame that fails `json.loads` → `raise StreamError`; AND an `httpx` transport fault from `aiter_lines()` → `raise StreamError`. (Stops swallowing real malformed frames without false-raising on benign keepalives.)
- **Q2 — minimax/ollama:** use a **pre-first-yield flag** (`yielded = False`). `httpx.AsyncClient.stream(...)` / `self._http.stream(...)` returns the context manager synchronously and only connects at `__aenter__` (inside `async with`), so a "open in its own try" cannot catch a connect fault — the flag is what actually classifies it. A single `except httpx.HTTPError` branches on `yielded`: a fault BEFORE the first yield (connection establish / handshake) → `NetworkError` (retryable, connection-time — preserves today's behavior); the same fault AFTER the first yield → `StreamError` (non-retryable, mid-stream). A malformed frame inside the loop always → `StreamError`. The old `except Exception -> NetworkError` catch-all is removed; 4xx/5xx status is mapped to typed errors via the existing status check, preserved by the typed-error `except (...): raise` guard. (`async with` auto-closes the response on every exit path.)
- **Q3 — StreamError stays NON-retryable:** it must NOT be added to `retry.py::_is_retryable` nor to the `client.py::stream_with` `except` tuple. Add a regression test asserting `stream_with` does not retry on it.
- **Q4 — deterministic close:** add `try/finally: await resp.aclose()` to `anthropic`/`openai`/`gemini` `stream()` (they rely on `return` today) so a mid-stream raise closes the response deterministically. In scope for F1. (`gemini_code_assist` already does this; `minimax`/`ollama` use `async with` which auto-closes.)

### F6 timeout error-type decision (resolved; open during review)

The Rust SDK uses a dedicated `MotosanError::StreamReadTimeout(secs)` for the stream path and `ProviderError("… timed out …")` for the blocking path (an intentional asymmetry). Python's `error.py` has no `StreamReadTimeout` analog and the existing claude_code/codex_cli timeout paths already raise `ProviderError`. **Resolution: reuse `ProviderError` for BOTH the blocking and the per-read stream timeout in all three CLI providers** — lowest churn, consistent across the three providers, and no shared `error.py` change to coordinate. The lost typed distinction is an accepted, documented divergence from Rust. **For parity hygiene (finding 9), the three per-read stream-stall messages are standardized on ONE phrasing: `"<provider> CLI stream read timed out after {n}s"` (claude/codex/gemini), and all three stall tests match the substring `"timed out"`. The three default timeout literals are all the same type (`float`): claude `300.0`, codex `600.0`, gemini `600.0`.** (Object here in review if a typed `StreamReadTimeoutError(MotosanError)` is wanted instead; it would be a separate `error.py` task threaded through F6.)

### `session_id` event-type decision (resolved; open during review)

Rust's `StreamEvent::session_started(id)` reuses `event_type = Text` and carries the id only on the `session_id` field. **Resolution: do NOT add a `StreamEventType.session_started` member.** CLI providers emit a plain `StreamEvent(content="", done=False, session_id=...)` (default `event_type="text"`), and `collect_stream` captures `session_id` from ANY event. This is Rust-faithful and avoids a public-enum addition not present in Rust. (`event_type` is typed `str` in Python; the codebase compares string literals — keep that convention; emit `event_type="tool_call_start"` etc. as strings, never the enum.)

## Milestone F1 — Fallible stream (FOUNDATION)

**Branch:** `feat/py-fallible-stream`

**Why:** Today every HTTP provider drops a malformed SSE/NDJSON chunk via `except json.JSONDecodeError: continue` and lets an `httpx` transport fault either escape raw or (minimax/ollama) get mislabeled `NetworkError`. A consumer cannot distinguish "the model finished" from "the connection died." F1 makes each `stream()` RAISE `motosan_ai.error.StreamError` on a parse/transport fault, and stops `client.stream_with` from retrying a mid-stream raise (which would replay already-yielded deltas).

**Outcome:** All 6 HTTP providers (`anthropic`, `openai`, `gemini`, `gemini_code_assist`, `minimax`, `ollama`) raise `StreamError` on a non-empty malformed frame or a transport fault; pre-filtered empty/`[DONE]` lines never raise; `client.stream_with` propagates a mid-stream raise without retrying; `collect_stream` propagation is proven by test. `StreamError` already exists (`error.py:29`) — no `error.py` change.

### Task F1.1 — Client: `stream_with` must not retry a mid-stream raise

`stream_with` (`client.py:324-378`) catches `RateLimitError/NetworkError/ProviderError` raised at ANY point during iteration.     """Provider stub that records how many times stream() was invoked."""

```python
    def __init__(self, make_gen):
        self._make_gen = make_gen
        self.stream_calls = 0

    async def stream(self, request):
        self.stream_calls += 1
        async for event in self._make_gen():
            yield event
```

```python
        for attempt in range(max_attempts):
            yielded = False
            try:
                stripper = ThinkStripper()
                async for event in self._provider.stream(request):
                    if event.event_type == "text" and event.content:
                        clean = stripper.feed(event.content)
                        if clean:
                            yielded = True
                            yield StreamEvent(content=clean, done=False)
                    else:
                        if event.done:
                            remaining = stripper.flush()
                            if remaining:
                                yielded = True
                                yield StreamEvent(content=remaining, done=False)
                        yielded = True
                        yield event
                return
            except (RateLimitError, NetworkError, ProviderError) as e:
                from motosan_ai.retry import (
                    DEFAULT_INITIAL_BACKOFF,
                    DEFAULT_MAX_BACKOFF,
                    _is_retryable,
                    _parse_retry_after,
                )

                # F1: once the stream has emitted any event, a mid-stream error
                # must propagate verbatim — retrying would replay a partially
                # consumed request and double-emit. Only connection-time
                # (pre-first-yield) failures are retried.
                if yielded or not _is_retryable(e):
                    raise
                last_error = e
                if attempt >= self._max_retries:
                    break
                retry_after = _parse_retry_after(str(e))
                wait = min(
                    retry_after
                    if retry_after is not None
                    else DEFAULT_INITIAL_BACKOFF * (2**attempt),
                    DEFAULT_MAX_BACKOFF,
                )
                logger.warning(
                    "Retryable stream error (attempt %d/%d), retrying in %.1fs: %s",
                    attempt + 1,
                    self._max_retries,
                    wait,
                    type(e).__name__,
                )
                await asyncio.sleep(wait)
        raise last_error  # type: ignore[misc]
```

```python
        body = self._build_body(request, stream=True)
        # Q2: an httpx fault BEFORE the first yield is connection-time
        # (NetworkError, retryable); after the first yield it is mid-stream

        yielded = False
        try:
            async with self._http.stream(
                "POST", f"{self.base_url}/api/chat", json=body
            ) as resp:
                if resp.status_code >= 400:
                    text = await resp.aread()
                    raise ProviderError(
                        f"Ollama error {resp.status_code}: "
                        f"{text.decode('utf-8', errors='ignore')}"
                    )

                async for line in resp.aiter_lines():
                    if not line:
                        continue
                    try:
                        chunk = json.loads(line)
                    except json.JSONDecodeError as exc:
                        raise StreamError(f"malformed NDJSON chunk: {exc}") from exc
                    if chunk.get("done"):
                        yielded = True
                        yield StreamEvent(content="", done=True)
                        return
                    msg = chunk.get("message", {})
                    content = msg.get("content", "")
                    thinking = msg.get("thinking", "")
                    text = content or thinking
                    if text:
                        yielded = True
                        yield StreamEvent(content=text, done=False)

                    for tc in msg.get("tool_calls") or []:
                        fn = tc.get("function") or {}
                        raw_args = fn.get("arguments", {})
                        if isinstance(raw_args, str):
                            args_str = raw_args
                        else:
                            args_str = json.dumps(raw_args, ensure_ascii=False)
                        tc_id = str(uuid.uuid4())
                        yielded = True
                        yield StreamEvent(
                            content="",
                            done=False,
                            tool_call_id=tc_id,
                            tool_call_name=fn.get("name", ""),
                            event_type="tool_call_start",
                        )
                        yield StreamEvent(
                            content="",
                            done=False,
                            tool_call_id=tc_id,
                            tool_call_args_delta=args_str,
                            event_type="tool_call_args",
                        )
                        yield StreamEvent(
                            content="",
                            done=False,
                            tool_call_id=tc_id,
                            event_type="tool_call_end",
                        )
        except (ProviderError, StreamError):
            raise
        except httpx.HTTPError as exc:
            if yielded:
                raise StreamError(f"stream transport error: {exc}") from exc
            raise NetworkError(str(exc)) from exc
```

## Milestone F4 — per-run env injection

**Branch:** `feat/py-cli-env`

**Why:** No way to inject per-run secrets into a CLI child. Rust added `.env(k,v)` (append) / `.envs(map)` (replace) stored in a `RedactedEnvs` newtype whose `Debug` prints `<N redacted>`, merged onto the inherited env via `cmd.envs(...)` (parent untouched). Python: a small `_RedactedEnvs` holder per provider whose `__repr__` hides values; child env = `{**os.environ, **injected}` (or `None` when empty).

**Outcome:** All 3 CLI providers gain `.env(k,v)` / `.envs(map)`; the child receives merged env; `repr(config)` shows `<N redacted>` and never the secret; `os.environ` is never mutated.

> **The three `_RedactedEnvs` are DELIBERATELY different shapes — do NOT unify them (finding 13).** claude (F4.1) and codex (F4.2) use a `list[tuple[str,str]]` subclass (`class _RedactedEnvs(list)`), iterated directly (`for key, value in self._config.envs`) and asserted via `list(client._config.envs) == [("A","1"), ...]` plus a `_subprocess_env()` helper. gemini (F4.3) uses a non-list wrapper with `.push()/.replace_from()/.as_dict()/__len__` and a `_child_env()` helper, asserted via `client._child_env()[...]`. Each provider keeps its own copy in its own file (no shared module, matching "no shared code between provider files"). A worker who "unifies" them will break the `list(...)` vs `.as_dict()`/`_child_env()` assertions — keep the per-provider shapes exactly as written below.

```python
class _RedactedEnvs:
    """Ordered env-var pairs whose ``repr`` never prints values (secrets)."""

    def __init__(self, pairs: list[tuple[str, str]] | None = None) -> None:
        self._pairs: list[tuple[str, str]] = list(pairs) if pairs else []

    def push(self, key: str, value: str) -> None:
        self._pairs.append((key, value))

    def replace_from(self, vars: dict[str, str]) -> None:
        self._pairs = [(str(k), str(v)) for k, v in vars.items()]

    def as_dict(self) -> dict[str, str]:
        return dict(self._pairs)

    def __len__(self) -> int:
        return len(self._pairs)

    def __repr__(self) -> str:
        return f"<{len(self._pairs)} redacted>"
```
